# Frontend - Kkulog

> 데스크톱 환경에서 사용하기 위한 캘린더 기반 일정 관리 앱

---

## 🎯 Frontend Goals

✅︎ 창 크기를 줄여도 달력 레이아웃이 무너지지 않도록 구현

✅︎ 일정 추가/수정 흐름을 단순하게 유지

✅︎ 데스크톱 WebView 환경에서도 레이아웃이 안정적으로 동작하도록 설계

---

## Tech Stack

### `React + Vite`
- 일정, 날짜 셀, 이벤트 바를 컴포넌트 단위로 분리하여 관리

### `TailwindCSS`
- 반복되는 UI(셀, 모달 등)를 빠르게 정리하기 위해 사용
- 디자인 수정이 잦아서 유틸리티 기반 방식이 편리했음

### `Tauri`
- 일단 가볍게 쓰려고 선택
- 데스크톱 환경을 전제로 개발
- WebView 기반 레이아웃 이슈를 고려한 화면 설계

---

## Frontend Architecture
```text
src/
 ├─ features/       # 일정, 캘린더 등 기능 단위 로직
 ├─ routes/         # 페이지 및 라우팅 정의
 ├─ store/          # 전역 상태 관리
 ├─ ui/             # 모달, 버튼 등 공통 UI 컴포넌트
 └─ layouts/        # 페이지 레이아웃 구조
```
---

## Features

- 📅 **월간 캘린더 화면**
  - 7일 단위로 계산되는 주 기반 그리드 구조
  - 한 달이 차지하는 실제 주 단위에 따라 5~7주까지 렌더링
  - 이전 달 / 다음 달 날짜가 함께 포함되며, 그 개수는 달마다 달라짐

- 📝 **일정 관리**
  - 모달을 통해 일정 추가/수정
  - 별도 페이지 이동 없이 처리
  - 시작일 / 종료일 선택 시 조건에 맞게 날짜 제한 처리

- 🖥 **데스크톱 환경 대응**
  - 창 높이에 따라 일정 표시 방식을 조정
  - 화면이 줄어들어도 `일정이 있다`는 정보는 유지하도록 설계

## 📒 Implementation Notes

### 1. 창 높이가 줄어들 때 일정이 보이지 않던 문제

창 높이를 크게 줄이면
캘린더 셀 내부 일정이 겹치거나 보이지 않는 문제가 발생했다.

이를 해결하기 위해,
셀의 높이에 따라 일정 표현 방식을 다르게 처리했다.

- 공간이 충분하면 텍스트 포함
- 부족하면 얇은 바 형태로 표시

UI가 줄어들어도 정보가 사라지지 않도록 하는 데에 집중했다.

---

### 2. 캘린더 렌더링 구조 고민

처음에는 일정 데이터를 각 day cell 안에서 직접 렌더링하려고 했다.

하지만 기간 일정(여러 날짜에 걸친 일정)을 처리할 때
구조가 복잡해졌다.

그래서 다음과 같이 분리했다
- `day cell` → 날짜 UI만 담당
- `event bar` → 기간을 계산해서 별도 레이어에서 렌더링

이 구조로 바꾸면서
일정 표시 방식이 바뀌어도 날짜 셀 구조는 그대로 유지할 수 있게 되었다.

---

### 3. visible range 기반 데이터 요청
달력은 단순히 "월" 단위로 고정되지 않는다.
한 달이 차지하는 실제 주 단위에 따라 5~7주까지 렌더링된다.

즉, 실제 화면은 월이 아니라
`현재 화면에 보이는 날짜 범위`를 기준으로 구성된다.

초기에는 월 전체 데이터를 조회했지만,
이 방식은 화면에 표시되지 않는 날짜의 일정까지 함께 가져오는 구조였다.

그래서 렌더링 방식에 맞추어 다음과 같이 변경했다.

- 현재 화면에 렌더링된 날짜 범위를 계산
- 해당 범위에 포함되는 일정만 요청

현재 표시 기간의 일정만 Tauri 명령으로 SQLite에서 조회한다.
여러 달의 데이터를 메모리에 캐시하지 않으며, 일정 변경 후에는 현재 기간을 다시 조회한다.
월 이동 중 오래된 조회 결과가 도착해도 현재 화면에는 반영하지 않는다.

## 실행

`frontend`에서 `npm install` 후 `npm run tauri -- dev`로 실행한다.
서버나 로그인은 필요 없으며, 로컬 DB 위치와 배포 빌드 방법은 [루트 README](../README.md)를 참고한다.
